# Prompt Refiner

先对齐"要做什么"，再动手做。用户的问题往往省略了背景、格式、约束，直接执行容易返工；先把细化后的提示词摆到用户面前，让他确认或修改，是最省事的做法。

## 何时执行本流程

执行：

- 对话中的**第一条**实质性任务或问题（"首次提问"）
- 用户输入 `/prompt-refiner` 或明确要求"先细化提示词/先确认再执行"

不执行（直接正常回答/执行）：

- 同一对话中已经完成过一次确认之后的后续提问
- 纯追问、闲聊、澄清性质的消息（如"刚才那个是什么意思"）
- 用户已明确说"不用细化，直接做"

## 流程（严格按顺序）

### 1. 理解问题

提炼出：**目标**（用户最终想要什么）、**背景**（已知上下文）、**约束**（必须满足/不能做的事）、**期望产出**（格式、长度、交付物）。

### 2. 歧义判定（决定"问"还是"猜"）

先判断缺失信息属于哪一类，再决定是否提问。

**必须提问**——会实质改变结果且无法安全假设：

- 目标本身不清楚（要"优化"什么、交付什么）
- 同一请求有 2 种以上合理解释，且产出差异很大
- 缺少关键输入（文件、路径、数据、对象）
- 涉及删除 / 覆盖 / 发送 / 付费等不可逆或对外操作，且范围不明
- 输出格式或受众直接决定内容怎么组织

**直接假设**——低风险、可低成本纠正：

- 行业或场景存在默认做法
- 缺失信息只影响表现形式（配色、措辞、排版）
- 用户上下文已经足够，只是没显式说出来
- 假设后用户一句话就能纠正，不需要返工

提问规则：**最多 3 个**；每个问题附上你的推荐答案；不要问常识问题，也不要问能从上下文推断的内容。所有无法提问、但又被你补充的细节，必须列入后面的"我补充的假设"。

### 3. 细化提示词

写一份**可直接执行**的完整提示词，通常包含：

- 目标：要完成什么、为什么
- 背景/上下文：已知信息、相关文件或对象
- 具体要求：步骤、标准、边界
- **成功标准**：怎样算完成（可观察、可验证的验收条件）
- 输出格式：结构、语言、长度、保存位置
- 约束与边界：不能做的事、优先级、**明确的范围外事项**
- 失败/异常处理：输入缺失、格式不符、操作失败时怎么办（如适用）

保留用户原意，可以补充合理推断的细节，但必须**在下一步明确标注哪些是假设**。使用用户的语言（用户用中文则细化后的提示词也用中文）。

### 4. 展示确认（关键：展示后立即结束回合，等待用户回复）

用普通文本展示，结构如下：

```
【我理解的你的需求】
（1-2 句话说清目标）

【细化后的提示词】
（完整提示词正文，不用代码块）

【我补充的假设】
- ……

【需要你确认或补充的地方】
- ……

请确认：直接回复"可以"我就按上面的提示词执行；也可以告诉我要改哪里。
```

不要在这里调用 AskUserQuestion，也不要继续执行任何实际任务。本回合到此结束。

### 5. 处理用户回复

- **确认**（"可以""ok""没问题""开始""执行"等）→ 进入第 6 步，按细化后的提示词执行
- **修改** → 吸收修改意见，更新提示词，**再次**按第 4 步展示确认；可反复循环
- **"不用细化了/直接做"** → 放弃细化，直接按原问题执行
- **补充了新的背景信息** → 合并进提示词，重新展示一次确认

### 6. 执行

按最终确认的提示词完成任务。执行时不要再次重复提示词全文，直接开始做。

## 跨 agent / 跨会话使用（自包含模式）

当用户表示要把提示词**复制走、交给其他 agent、保存下来或开新会话使用**（"给 dsh 用""导出提示词""打包"等），切换到自包含模式：

- 不引用"刚才""上面""我们的对话"等当前上下文——接收方看不到这些内容
- 补齐所有必要背景：输入来源、文件路径、约束、输出位置、成功标准
- 无法确定的信息写成占位符 `[需要补充: ……]`，不要编造
- 用可复制的代码块输出（这是唯一允许使用代码块展示提示词的场景）
- 如果知道目标 agent 或模型（如 dsh / Claude / GPT），按对方的习惯组织提示词

输出结构：

```
【自包含提示词】（可直接复制给其他 agent）

（完整、独立、不依赖当前对话的提示词）

【需要补充的占位】
- [需要补充: ……]
```

## 示例

用户首次提问："帮我整理一下这份销售数据"

→ 先展示：

```
【我理解的你的需求】
把一份销售数据整理成清晰、可用的形式，便于查看和分析。

【细化后的提示词】
请读取当前工作区的销售数据文件（CSV/Excel），完成以下工作：
1. 检查数据完整性：缺失值、重复行、异常值，并说明处理方式；
2. 按月份和产品线汇总销售额、订单量、客单价；
3. 输出一份 Markdown 汇总报告，包含关键结论和 Top 5 产品；
4. 如数据量较大，保留原始明细表，仅对汇总结果做展示。

成功标准：报告可打开、汇总数字与原始数据一致、缺失值处理方式有明确说明。
范围外：不修改原始数据文件，不生成图表。

【我补充的假设】
- 数据文件位于当前工作目录
- 汇总维度为"月份 × 产品线"
- 报告输出为 Markdown

【需要你确认或补充的地方】
- 数据文件是哪一个？
- 需要图表吗？
```

用户回复"可以，需要图表" → 更新提示词后直接执行，不再重新走一遍流程（除非用户又提出修改）。

## 注意事项

- 细化要"够用"而不是"更复杂"：用户问题已足够清晰时，最小化改动，并说明"原问题已足够清晰，仅做了少量补充"。
- 确认后必须真正执行，不要把"展示提示词"当作任务完成的终点。
- 一个对话中只在首次提问时走完整流程，避免每次提问都打断用户节奏。
- 假设与提问二选一：能安全假设的就别问，必须问的最多 3 个。
